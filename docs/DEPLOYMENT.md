# VercelでWebアプリを公開する

## 現在の状態

Vercel向けの公開設定を用意した段階です。まだ公開URLは発行されていません。クラウド開発環境の「Publish」と、Webアプリのデプロイは別の操作です。

このクラウド環境ではVercelへの通信が制限され、Vercelの認証も登録されていません。GitHubの公開用コードとローカルの本番ビルドを準備し、最後のログイン・Import・DeployをVercelの画面で行います。認証トークンやパスワードをチャットへ貼る必要はありません。

## 初回の公開

1. [Vercelの新規プロジェクト画面](https://vercel.com/new)を開き、GitHubアカウントでログインします。
2. `allaaffet/thai-learning-app` を探して「Import」を選びます。表示されない場合はGitHub連携のリポジトリ権限に、このリポジトリを追加します。
3. 次の設定を確認して「Deploy」を押します。公開用のブランチは最新の内容を反映した `main` を使います。

| 設定 | 値 |
| --- | --- |
| Framework Preset | Next.js |
| Root Directory | リポジトリ直下（変更不要） |
| Node.js Version | 24.x |
| Install Command | `npm ci` |
| Build Command | `npm run build` |
| Output Directory | Next.jsの標準設定（変更不要） |
| Environment Variables | 追加不要 |

`vercel.json` にFramework・Install・Buildを記録しています。Node.jsはVercelのプロジェクト設定でも24.xを選びます。既存の `.node-version` と `package.json` の対応範囲を維持します。データベース、アプリ用APIキー、独自ドメインは不要です。

完了すると、VercelがHTTPSの `*.vercel.app` URLを発行します。実際に表示されたURLを使い、プロジェクト名だけからURLを推測しないでください。個人用プランで始められますが、プランの利用条件・上限はVercelの画面で確認してください。

## 公開後に確認すること

- PCとスマートフォンでホームを開き、「学習の冒険」へ進める。
- ミッション内の解説、めくり、回答、理由、結果の記録、再読み込みが動く。
- 音声カードを1回押すと再生し、次のカード・別画面への移動で停止する。端末にThai音声がない場合は文字で続けられる。
- 文字トレーニングのカスタム指定、書き取りの指定付きURL、字体切替が動く。
- フォント・教材のライセンス表示へアクセスできる。

公開先の確認が終わるまで、公開環境で動作確認済みとは扱いません。教材・端末合成音声は引き続き専門家監修前です。

## 学習記録とマイク

進捗はアドレスとブラウザごとに別保存です。localhost・LANのIPアドレスで学んだ記録は、公開URLへ自動移行しません。元のアドレスの記録はそのまま残ります。別端末・別ブラウザとの同期もありません。

VercelのHTTPSはマイクを使うための接続条件を満たしますが、実際の利用には端末・ブラウザの対応と、利用者の許可が必要です。公開しただけでマイクが起動することはありません。音声認識はブラウザ提供元へ通信する場合があります。

## 更新と切戻し

GitHub連携後は、公開用の `main` に取り込んだ変更をVercelがビルドします。開発ブランチの変更だけでは本番の更新とは限りません。次回も公開対象のコードを確認し、検証後に `main` へ反映してください。

更新で問題が起きた場合は、VercelのDeployments画面から以前の正常なデプロイへ戻します。Git履歴や利用者の進捗を削除して戻す方法は使いません。

## 開発上の注意

このアプリは通常のNext.jsホスティングを使います。`/writing` と `/character-practice` はサーバー側で検索パラメーターを扱うため、公開のためだけに `output: "export"` へ変更しません。

Vercel CLIのローカル接続情報 `.vercel/` はGitへ含めません。`.vercelignore` は生成物・テストレポート・環境ファイル等をCLIアップロードから除外します。秘密情報はVercelのEnvironment Variablesへ登録し、ソースやチャットへ書きません。
