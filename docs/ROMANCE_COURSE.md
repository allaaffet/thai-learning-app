# 恋するタイ語 — 実践編

## ねらいと範囲

学習メニューの `/romance`（街のデート編）と `/romance/campus`（キャンパス恋愛編）に、架空の成人キャラクターとの交流を通してタイ語を使う実践コースを設ける。日本語の物語、モデル付きの短いThai会話、相手への接し方を選ぶ場面を組み合わせる。タイ語の正誤と、物語内の好感度・関係性を明確に分ける。

このコースは台本型の恋愛シミュレーションであり、実在人物・自由なAI会話・現実の恋愛相談ではない。キャラクターは全員27〜32歳の架空の成人。露骨な性的表現、実在の相手への連絡、課金による好感度、欠席による好感度の減少は設けない。

本編の30課・150問・1210XP、前提、SRS、文字練習と既存会話の記録は引き継ぐ。恋愛コースの進行を、本編の解放条件や習熟度へ加算しない。

2026-11-03の改修では、標準体験を人物ごとの分岐と段階的な会話練習を持つストーリーへ変更する。詳細は [ROMANCE_JOURNEY.md](ROMANCE_JOURNEY.md)。この文書では引き継ぐ人物・5話・好感度・旧保存の基本仕様を記録する。従来の3問形式は `/romance?view=classic` から利用できる。

街では夜の待ち合わせや二人きりのデート、キャンパスでは成人が通う大学の社会人向け夜間講座の隣席・放課後・学園祭を扱う。物語の相互の好意を具体的にし、触れ合いを選ぶ場面も気持ちを急がない応対も肯定的に描く。語学の高得点を親密な行動の報酬にしない。舞台と独立保存は [ROMANCE_SETTINGS.md](ROMANCE_SETTINGS.md) を参照する。

## はじめ方と相手

1. 主人公の設定を「男性」「女性」から選ぶ。実在の本人確認を求めず、この物語で使う役の設定として扱う。
2. 好みを `warm`（明るく親しみやすい）、`calm`（落ち着いて穏やか）、`curious`（知的・好奇心）から選ぶ。
3. 異性の3人を表示する。各キャラクターは2つの傾向を持ち、好みに合う2人を先に紹介する。ほかの相手も選べ、複数人の関係を別々に育てられる。

男性・女性を各3人用意する。Mali・Rin・Dao、Arun・Kiet・Niranは物語の登場人物名であり、名前のThai綴りや発音を新たな教材として推測生成しない。主人公の設定や好みを変更しても、これまでの相手別記録を消さない。進行中の未記録の会話は、設定変更や画面離脱で終了する。

性別に合わせた話し方はモデルの推奨として示す。既存教材に登録した複数の丁寧な正答を保持し、もう一方の丁寧詞を選んだことだけで不正解にしない。男性キャラクターのモデルでは、登録された語句IDを使って文末詞を明示的に切り替える。性別から自然な発話すべてを機械的に決める規則にはしない。

## エピソードと学習

各相手に5話を用意し、前の話を終えると次へ進める。好感度の高さや満点を解放条件にしない。

| 順序 | ID | 主な場面・会話 |
| --- | --- | --- |
| 1 | `meet` | 挨拶、話す誘い、会えてうれしい |
| 2 | `cafe` | 隣席、あなたと話したい、一緒に行く |
| 3 | `likes` | 褒め言葉、あなたが好き、恋しい気持ち |
| 4 | `market` | 明日の予定、デートの誘い、また明日 |
| 5 | `walk` | また会いたい、再会の約束、おやすみ |

標準体験の1話は人物別の2ルート選択→モデル→語句の組み立て・本番3問・過去話の表現→誤答の追加練習→場面に沿った2つの物語選択→明示記録で進む。人物とルートで課題・反応・思い出・次話へのきっかけを分ける。ルートはどちらも妥当とし、恋愛場面の相手への返事としてタイ語を使う。従来の3問形式でも会話内容を同じ新教材に揃える。詳細は [ROMANCE_DIALOGUE.md](ROMANCE_DIALOGUE.md)。

お手本・日本語訳・ヒントを参照でき、音声なしでも続けられる。選択直後に音を確認できる操作と、返答を確定する操作は分ける。正誤は目標に合う意味の判定であり、発音・声調・現実の会話能力の採点ではない。誤答時には理由と受け付ける表現を示し、有限の手順で次へ進める。

物語の選択は日本語で提示する。思いやり、相手の好み、断り方などに対する物語上の反応であり、Thaiの正誤と混同しない。丁寧に断る選択も使え、同意や好意を無理に求める内容にしない。

## 好感度・関係性・毎日の継続

好感度は相手ごとに0〜100へ収めるゲーム内の値で、言語習熟度・実在人物の気持ちではない。関係性は0・20・40・60・80を区切りに段階表示し、5話の終了後には現在の好感度に応じた物語の結びを参照できる。

各エピソードの初回終了時だけ、次の変化を適用する。言語点に使うのは従来と同じ本番3問の初回回答で、組み立て・想起・追加練習を混ぜない。

| 内訳 | 好感度への変化 |
| --- | --- |
| 会話3問 | `正解数 × 2 − 誤答数`（−3〜+6） |
| その話の初回終了 | +2 |
| 物語の選択 | 相手に合う思いやり +3、穏やかな選択 +1、配慮を欠く選択 −2 |

同じ話を繰り返しても、この初回分の変化は再び得られない。会話の記録・表示では、正答数と物語の選択、日々のボーナスを別に示す。小さな減少があっても再練習や次の話を止めず、あとから回復できる。

その相手と、そのローカル日付で最初に会話を終えて記録すると+2。前日も記録していた場合はさらに+1で、1日最大+3とする。表示・相手の選択・同日の再記録だけでは付与しない。日付が戻った場合や未来の記録がある場合も、同じ日を重ねてボーナスへ変換しない。休んだ日には好感度を減らさず、責めるメッセージや復帰のカウントダウンを作らない。

## 保存とプライバシー

独立した `thai-learning.romance.v1`、版 `1` に主人公の設定、好み、相手別の好感度・終了した話・学習日・重複防止情報を保存する。すべてこのブラウザ内で扱い、アカウント・外部DB・別端末同期を追加しない。自由入力の会話、録音、音声認識、画像のアップロードは行わない。

設定の確定と、全ての会話・物語選択を終えた明示的な記録だけで保存する。読込み時に空の状態を書き込まず、未知版・壊れたJSON・未知ID・不正な値は信用しない。不正な元データは、利用者が明示的に置換するまで保護する。保存できない場合はこのタブで続け、保存済みと誤認させない。

同じ終了操作の重複、終了前の記録、未解放の話、現在の主人公設定に合わない相手の古い操作を拒否する。他タブの記録は既存の範囲を保って取り込む。主人公設定を変更したときは画面の相手を選び直し、過去の相手の記録自体は保持する。

新コースの実際の活動・ヒント・終了したルートは `thai-learning.romance-learning.v1` に別保存する。旧履歴から新しい練習を済ませたとは推定しない。旧終了処理が受け付けた後に新しい活動を記録するが、2つの保存を一括成功と保証せず、各保存の状態を表示する。詳細は [ROMANCE_JOURNEY.md](ROMANCE_JOURNEY.md) を参照する。

キャンパスでは同じ版と保存処理を、`thai-learning.romance-campus.v1` と `thai-learning.romance-campus-learning.v1` の2つのキーへ対応させる。街と学園は役・好感度・パスポート・思い出を別に持ち、切替時に未記録の会話を別の舞台へ持ち越さない。未知版の原文保護、明示置換、StorageEventは選択中の舞台に限る。

## 教材・音声・画像の品質

恋愛専用の15ターン・52語句を使う。追加16語句の辞書形IPAと一部の語義を照合した範囲に限って記録し、会話全文・日本語訳・使い方は未監修とする。出典と実際の確認範囲は [ROMANCE_DIALOGUE_SOURCES.md](ROMANCE_DIALOGUE_SOURCES.md) に記録し、全文IPAを語のIPAの連結で生成しない。本編・独立会話のカタログは維持する。

音声は登録したThai表現に対する任意の端末TTSで、ネイティブ録音ではない。押した操作内で再生し、表示・保存復元・次のやり取り・物語の展開では自動再生しない。録音・マイク・ASRをこのコースから開始しない。移動・離脱で再生を止め、タイ語の声がない端末では別言語へ代替せず、文字と訳で続ける。

SEは既存の設定・初期オフ・音声優先を使う。新ストーリーでは組立・会話本番・想起・最大1回の修復それぞれの初回確定回答に使い、従来形式では会話問題の初回確定回答に使う。同じ活動の再確定、物語の選択や好感度の変化には追加SEを付けない。好感度を発音評価の正解音で保証しない。表示・日付変更・記録復元・物語の終了だけで追加再生せず、新しい音源・有料APIを導入しない。

人物画像は実写を使わず、オリジナルの2Dイラストを採用する。素材の構成は3列×2行の人物シートで、女性役を上段、男性役を下段に配置する。女性陣の柔らかな漫画の画風と、男性陣の少しシャープな漫画の画風を使い分け、6人の髪型・顔立ち・肌の色・体格も変える。実在人物ではなく成人の架空人物として描く。採用素材と人物配置は [ROMANCE_ART.md](ROMANCE_ART.md)、動作・表示の確認結果は検証記録へ残す。

新コースでは通常・笑顔・考える・優しく確認する表情を場面に合わせて使う。実際の学習者の発音や感情を判定した演出ではなく、誤答を責める表情は設けない。

## 実装と検証

- `src/lib/romance-types.ts`：役の設定、登場人物、エピソード、問題、物語選択の型。
- `src/data/romance.ts`：登場人物、台本の参照、追加例、文末モデル、出典、物語の反応。
- `src/lib/romance.ts`：判定、解放、好感度、日次ボーナス、保存検証・重複防止。
- `src/components/use-romance.ts`：ブラウザ保存とメモリ内の状態、他タブ、保存不可・復旧。
- `src/components/romance-course.tsx` と `src/app/romance.css`：設定、相手、会話、物語選択、結果。

ユニットでは教材の参照・複数正答・語句保持、好感度の範囲、再演の非加算、日付・連続・時計逆行、他タブと不正データ保護を確認する。ブラウザでは両方の主人公設定、好み、複数相手、全話・再開・再演、音声の1操作再生、文字拡大・キーボード・スマートフォンを確認する。結果と未確認の範囲は [VALIDATION.md](VALIDATION.md) に記録し、実機の音質や専門家監修と模擬APIの検証を区別する。
