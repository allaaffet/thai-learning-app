# 恋するタイ語 — 会話を育てるストーリー

## 改修のねらい

2026-11-03の追加依頼に基づき、`/romance` の標準体験を、決まった3問を答えるだけの流れから、物語の分岐と段階的な練習を持つコースへ改修する。6人の架空の成人、5話のID、既存の好感度と完了履歴を引き継ぐ。従来の3問形式は `/romance?view=classic` で参照できるようにする。

学習の軸は「何を伝えるかを知る→登録された語句で組み立てる→相手への返答を選ぶ→前の場面で使った表現を思い出す」。物語の好感度、活動を行った記録、その回のヒントなしの確認を区別し、会話能力や発音の保証にはしない。

街のデート編 `/romance` は、二人だけの時間、率直な誘い、好意を伝える選択を人物別に描く。新しいキャンパス恋愛編 `/romance/campus` は、大学の社会人向け夜間講座を舞台に、隣席から放課後・学園祭・帰り道へ関係が進む。どちらも成人6人と24表情、同じ会話機能を使い、物語と記録は分ける。舞台別の仕様は [ROMANCE_SETTINGS.md](ROMANCE_SETTINGS.md)。

三人から同時に誘われる入口と、他の二人も登場する個人ルートを持つ。締めの選択ごとに反応・表情・次の予告を変え、明示的に終了した話の `lastStory` から次話の続き・パスポート・最終話の結びを表示する。旧記録の選択は推測しない。詳細は [ROMANCE_ENSEMBLE.md](ROMANCE_ENSEMBLE.md)。

## 5段階のカリキュラム

| 話 | 会話の機能 | 本番での既定の支援 | 積み上げる練習 |
| --- | --- | --- | --- |
| `meet` | 挨拶・話す承諾・会えてうれしい | モデル | お手本と訳を見て返す。短い語句を並べる |
| `cafe` | 隣席・あなたと話したい・一緒に行く | モデル | 距離を近づける誘いに返答し、挨拶も確認する |
| `likes` | 褒め言葉・好きな相手・恋しい気持ち | 意味の手がかり | 似た表現の意味を区別し、好意を言葉にする |
| `market` | 明日の予定・あなたと行きたい・また明日 | 想起 | ヒントを使い、デートの誘いから約束へつなぐ |
| `walk` | また会いたい・再会の約束・おやすみ | 想起 | 別れ際の気持ちを返し、次に会う日へつなげる |

教材の支援は `model`・`meaning`・`recall` と段階化する。後半でも新しい話のお手本は既定で提示し、予習を省く場合は利用者の明示操作にする。ヒントを使ったことへの罰や、満点を要求する進行条件は設けない。前の話の終了で次へ進める。

本番の3問は、依頼からお礼までの因果関係を保つ元の順番で扱う。分岐で練習の焦点や語句の組み立て・想起の順序を変えても、買う返答のあとで値段を初めて尋ねるような不自然な会話順にしない。過去の想起は、その話より前の話から選ぶ。

## 1話の進み方とゲーム性

1. 相手固有の導入を読み、その日の2つのルートから行き先や過ごし方を選ぶ。
2. 場面の小さな課題と、今回使う会話のお手本を確認する。
3. 登録語句の並べ替え、会話本番の3問、前の話の想起に取り組む。組み立てと想起を行う位置はルートで変わり、本番3問の因果順は固定する。
4. 間違えた活動は理由と受け付ける表現を確認し、最大1回の追加練習で確かめる。
5. その場面に沿った2つの行動から、物語の応対を選ぶ。
6. 明示的に終了を記録し、会話の振り返りとルート固有の思い出カードを見る。

各人物・各話に `listen` と `lead` の2ルートを用意する。どちらも妥当な選択で、正解ルートを当てる問題にはしない。場所、起こる小さな課題、練習の焦点、相手の反応、思い出、次の話へのきっかけが変わる。同じ人物でも別のルートを選んで、別の思い出を集められる。

人物一覧と会話パスポートでは、実際に練習した会話の機能・ルート・活動を振り返る。旧版で話を終えていても、新しい組み立て・想起を行ったとは推定しない。収集物は本編のXPや資格ではなく、選んだ場面と実践の記録とする。制限時間、ハート、欠席を責めるメッセージ、課金で関係を戻す仕組みは追加しない。

## 解答・ヒント・音声

組み立ては、登録された `wordIds` の語句を選んで順に並べる。Thaiの文字列を推測して分割せず、語句の重複・不足・余分な語・順序を検査する。既存の男性形・女性形の丁寧な返答を受け付け、主人公の性別だけで正答を狭めない。

初回の確定回答を固定する。ヒントや解説を見た後の追加練習で、本番の初回成績を書き換えない。理由と受け付ける表現をすぐ確認でき、誤答でも有限の手順で次へ進める。ヒント使用や「ヒントなしで確認した数」はその活動の記録であり、自然会話・発音・長期定着を認定する値ではない。

Thai音声は既存の任意の端末TTSを使う。聞くボタンや音を確認する返答の選択と同じ操作内で再生し、表示・次の活動・表情の変更・ヒントの展開だけでは再生しない。音声が使えない端末でも、文字と訳で続けられる。マイク・録音・音声認識・外部AI会話は追加しない。既存のSE設定と教材音声の優先を守り、組立・本番・想起・最大1回の修復の各活動を初めて確定した操作だけで既存SEを1回要求する。語句や返答を選んだだけの操作、モデル・ルート・表情・物語選択・保存・結果では追加SEを鳴らさず、物語の好感度を発音判定の音で表さない。

## 表情と教材の品質

表情は `neutral`・`happy`・`thoughtful`・`concerned` の4種類を設ける。導入、考える場面、伝わった場面、言い直しを助ける場面に合わせて使う。誤答に対する怒り・軽蔑・落胆の罰にせず、台本内の演出として扱う。実際の学習者の声や感情を推定した表情ではない。

画像は既存の6人の成人らしい外見と、男女で異なる漫画の画風を引き継ぐ。生成素材と採用確認は [ROMANCE_ART.md](ROMANCE_ART.md)、実画面の確認結果は [VALIDATION.md](VALIDATION.md) に記録する。

Thaiは恋愛専用の52語句・15ターンを使う。追加16語句の辞書形IPAと一部語義を資料と照合し、会話全文・日本語訳・丁寧詞の自然さは未監修とする。全文IPA、声調分析やネイティブ録音は生成しない。場面に合う表現と照合範囲は [ROMANCE_DIALOGUE.md](ROMANCE_DIALOGUE.md) と [ROMANCE_DIALOGUE_SOURCES.md](ROMANCE_DIALOGUE_SOURCES.md) を参照する。

## 保存と互換性

| 保存先 | 記録する内容 |
| --- | --- |
| `thai-learning.romance.v1`、版 `1` | 従来の主人公設定・相手別好感度・5話の本番3問と完了・日次ボーナス |
| `thai-learning.romance-learning.v1`、版 `1` | 新コースで実際に終了したルート・組み立て/本番/想起の集計・ヒント使用・思い出の導出に必要な記録 |

旧本番3問の初回回答と対応する物語選択を、従来の終了処理へ渡す。それが受け付けられた後だけ、新しい活動記録を終了処理へ渡す。組み立て・想起・リカバーを、好感度の言語点や本編のXPへ加えない。2つの保存への一括書込みは保証せず、それぞれの保存失敗を表示する。

新しい保存も読込みだけでは書き込まない。未知の版・不正な原文を明示的な置換まで保護し、保存できない場合はタブ内で継続する。終了セッションの重複、活動や語句の不正な参照、未完了の活動を検証する。既存の本編30課・150問・1210XP、前提、SRS、独立会話、文字練習、クエストやバッジへの書込みは行わない。

2026-11-04の会話変更では、活動の話に任意の `curriculumId` を追加する。現行IDで終了した話だけ新表現の完了数へ数え、項目なしの旧履歴は「以前の会話の記録」として保持する。物語の解放や思い出は維持し、後半から再演して初めての表現が出ても、お手本とヒントで確かめられる。

キャンパスの記録は同じ版 `1` の `thai-learning.romance-campus.v1` と `thai-learning.romance-campus-learning.v1` へ分ける。街の既存キーを維持し、舞台の切替で画面をキー付きで再マウントする。保存アダプターとStorageEventも舞台を指定し、原文の保護や明示置換を他の物語へ広げない。

## 実装の責務と検証

- `romance-journey-types.ts` と `src/data/romance-journey.ts`：会話機能、支援段階、街のルート構築を管理する。日本語の物語は `romance-stories-female.ts`・`romance-stories-male.ts` と `romance-story-types.ts` に分ける。
- `romance-setting.ts` と `data/romance-story.ts`：舞台・保存キーと場面の選択を管理し、キャンパスの場面を `romance-campus.ts` から取得する。
- `src/lib/romance-journey.ts`：活動計画、組み立てと返答の判定、旧本番3問の抽出、新しい活動記録と保存検証を扱う。
- `use-romance-learning.ts`：新しいブラウザ保存とタブ内状態を管理する。
- `romance-journey-player.tsx` と `romance-journey.css`：分岐と学習、表情、振り返りを表示する。
- 既存の `romance-course.tsx`：主人公・相手・話の選択、好感度、新旧体験の導線をまとめる。

教材の参照と前提、両方の丁寧な正答、順列と初回回答、支援段階、過去話だけの想起、再送信・未知版・保存拒否・他タブを検証する。ブラウザでは両方の主人公とルート、有限の誤答復習、表情、狭い画面・文字拡大・キーボード、1操作の音声、旧履歴と他の保存領域への非干渉を確認する。実行結果は [VALIDATION.md](VALIDATION.md) に記録し、未確認の実端末音質や専門家監修と区別する。
